# Per-state config templates (Phase 6)

One `<CODE>.json` per gathered state (32), generated by `../build_state_templates.js` from:
`../workflow_overlay.json` (115 classified flow nodes, v2.5) × `../node_concept_map.json`
(the Phase-6 bridge: every one of the 122 canonical concepts assigned to a config surface) ×
`../../alignment/master_concept_dictionary.json` (concept → per-state member rules) ×
`../../pruned/pruned_discovery.json` (1,117-rule working set).

## Template shape

| Section | What it is | Fill rule |
|---|---|---|
| `knobs` | the 30 ◆ value-knob nodes | every knob needs a value in every state; `statutory` blocks are the evidence (rule id · authority · clock_spec · summary); `city_config` marks what stays local policy (the diagram's ⚠ config-not-law edges), with suggested defaults |
| `branches` | the 25 ▲ state-gated nodes | `active` true/false per state, driven by `activated_by` concept presence; `context` concepts are evidence that never activates (e.g. `eligibility.any_person` proves the gate is OFF); `states_override` used only where a concept is broader than the branch (deny-as-vague, TX programming loop); `complement_of` for collect-at-end (ON where prepayment is NOT statutory) |
| `clock_matrix` | 10 named timers | the clock is engine machinery, not a flow node; `present:false` = soft-standard → city operational target (S-002) |
| `fee_schedule` | the per-state fee data table | feeds the shared ledger compute node `f1` |
| `program_setup` | org-level obligations | records-officer designation, written policy, fee-schedule authority, denial log … |
| `ledger` | requestor-ledger triggers | classes A–D per `../DESIGN_requestor_ledger.md` |
| `audit` | coverage check | every state rule must be reachable through the mapping (currently 1,117/1,117 across all states; generator fails loud otherwise) |

`SUMMARY.json` = one row per state (active branches, statutory timers, rule counts).
Kevin-readable copies: `exchange/config_templates/` (32 HTML + index + `Config_templates.xlsx`
with Summary / Branch-matrix / Timer-matrix sheets) via `../../scripts/gen_template_deliverables.js`.

## Data fixes made while building (2026-07-26)

- **TX-0009/0010 re-homed** `production.certified_copy` → `production.completion_window`: the
  10-bd delay/active-use certifications are the TX production clock's checkpoints; the regex
  bucketer's `/certif/` had swallowed them. Fixed via `RULE_OVERRIDES` in
  `alignment/build_master_dictionary.js` (rule-id-level, auditable, rerunnable).
- **TX-S05 added** (supplements/completeness_additions.json): Tex. Gov't Code § 552.221(e)
  60-day unclaimed/nonpayment withdrawal — was on the Disposition diagram (from desktop research)
  but missing from the working rule set. Verified verbatim (texas.public.law, current through
  2025-05-26). Working set: 1,116 → **1,117 rules**; concepts unchanged at **122, 0 catch-alls**.
- TX has no separate `initial_decision` window by design: its statutory clock IS the production
  ("promptly") clock — the template renders that faithfully (completion timer present,
  initial-decision absent).
