MRR packaging & timing — the city's two blank rows 9

delivery_mode (as_ready · hold_all) and notice_packaging (per_child · combined) are MRR Rule-Matrix rows shipped blank — the city answers them with counsel before MRR unlocks, and they are presented together because answering them inconsistently reads awkwardly. For a single-record request both produce one record, one shipment, one notice — n = 1 degenerates correctly. Where statute makes installments an entitlement (WA), hold_all is not selectable.
RM hold of a ready record (MRR): requires a note, and in an entitlement jurisdiction a requestor's request for installments overrides it — drafted per the recommended guard, which is flagged OPEN and unratified; the override does not build until it is resolved. Never a payment hold (§5.9). 10
When the last child ends 12

The parent derives Complete — no parent disposition exists, whatever the children's mix; each child keeps its own ending. On an MRR, the last child reaching ready already triggered Draft 7's settlement; the last closure completes the parent and ends the MRR Management task.

Design annotations

  1. A close surface opened from a task, returning to it — same pattern as Denial compose. Dispositions are child-level, the eight §5.8 endings, verbatim; nothing else is offerable and the parent is never closable.
  2. Every ending has its own evidence gate, named on the option. Withdrawn needs the withdrawal on file (a choice, not silence — the distinction from No response is the point of having both); referral needs the custodian named; the gate chips say what is missing before anyone commits to an ending.
  3. RULE-pattern The no-records gate is the worked example: non-empty effort trail + every duty-carrying description answered + a required reasoning note — and the two gates never feed each other (an intent answer is a claim, not evidence), the record-search spec's own firewall, restated where it bites.
  4. Denied is visible but locked — reachable only through Denial compose or the AG band, because its content requirements (citation, explanation, letter) live there. Showing it locked teaches the path; hiding it would just get it asked for.
  5. Previously furnished is an ending, not a denial (TX §552.232) — gated on the certification (prior request reference, date, match). State-specific endings appear only where their state provides them (rule-b posture).
  6. RULE C Sweep closures are records, not surprises. No response / Non-payment normally close by the config-gated sweeps — shown with the system-per-attested-config badge, the numeric basis (grace + buffer; the 60-day window), and the notice trail. Manual use of either demands the same evidence the sweep would have had.
  7. Every closure owes a notice. Content is per-disposition and — for denials — invariant (exemption, citation, application). The close button is one act: disposition + notice, never a silent end. Blocked-with-reason, as everywhere.
  8. Delivered is written by the release event, not asserted: release + funds check + notice + `delivered_at` + `installment_no` as one event. A redacted release is still Delivered — the withholding log (§5.7) carries the detail, which is why no “partially granted” disposition exists or is needed.
  9. §15 The two MRR matrix rows ship blank and are presented together (delivery_mode × notice_packaging): a shipped default here would be the vendor making policy for a government. n = 1 degenerates correctly; WA's entitlement removes hold_all from the menu (constraint, not default).
  10. ⚠ The RM-hold guard is drafted but OPEN. Note-required + requestor-override-in-entitlement-jurisdictions is the spec's recommended, unratified guard — the mockup encodes it so Kevin can ratify or reverse; the override does not build until resolved. It is never a payment hold (§5.9).
  11. Reopen needs a real guard. The transition engine currently has no from-closed guard (flagged doc-debt); drafted as Director-authority + required note, and the guard becomes part of this build, not a later fix.
  12. The parent's ending is derived, never chosen. All children terminal → Complete; mixed endings stay per-child (the retired “partially granted” roll-up stays retired); the mixed-outcome notice question remains with the notices field-design pass, deliberately not answered by this screen.
