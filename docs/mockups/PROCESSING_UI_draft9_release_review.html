Design annotations

  1. KEVIN 7/29 A real task type: release_review. Spawned by the pipeline's gate branch (conditions met + gate ON → task instead of shipment); routed by config in the approval-modules pattern — suggested default ORO Supervisor; "Release Review" joins the Supervisor / Director task menus (optionally team supervisors). Eligibility via user_task_types; pool + smart routing unchanged.
  2. Two entries, one queue. The group header carries "Power mode (n) →"; every row still opens one-at-a-time. Power mode is an accelerator, not a replacement — the slow path is always there.
  3. The two-eyes rule: the reviewer is never the person who completed the item's last flow task — enforced at assignment, not etiquette. (Open question: widen to any flow task on the item? Small-city reality argues narrow.)
  4. KEVIN 7/29 Power mode is populate-in-place: approve → the item's data disappears, the next request's data fills the same screen. No My-Tasks round-trips. Keyboard-driven (A / S / R). Ordering is the queue's clock-aware order, nearest deadline first.
  5. The substance sits on the surface. Released set, the withholding log with citations, the notice as the requestor receives it, and the item's flags — nothing reviewable hides behind a click, so speed never equals blindness.
  6. Skip is honest: the task stays in the queue untouched (for the one that needs a phone call); skipped items resurface at the end of the pass (open question: or hold until next session?).
  7. RULE C No rubber-stamp mechanics. Every approval is an individually recorded act — this reviewer, this item, this timestamp, audit-identical to the one-task path. No bulk-approve, no select-all; the unit of action is one item, always. Drafted metrics for oversight: counts only, no per-reviewer timing (open question).
  8. The progress strip keeps the pass honest: position, remaining, skipped — the reviewer always knows what the session has and hasn't covered.
  9. Return-with-note is the review's teeth (Draft 4's return-with-guidance pattern): required note, lands on the producing task, pipeline re-arms on the fix. Silent to the requestor — nothing has been promised. Without this button the review would be ceremony.
  10. The pattern is deliberately scoped (first-build lesson): PowerQueue is a component-library shell (progress strip + act row + populate-in-place) instanced per task type — release review first. Future candidates, each its own tuned variant, none in v1: the close_approval = approval_required supervisor queue, routed waiver decisions.

Columbus, OH in one line: identical — the gate is city policy (the go-live knob), not law; the withholding log simply cites R.C. exemptions instead.
